================================================================================
เอกสารข้อกำหนดความต้องการซอฟต์แวร์ (Software Requirements Specification - SRS)
ชื่อระบบ: ระบบติดตามการดำเนินงานของนิสิต (Student Progress Tracking System - project_fiveper)
================================================================================

1. วัตถุประสงค์ของระบบ (System Purpose & Overview)
--------------------------------------------------------------------------------
ระบบติดตามการดำเนินงานของนิสิต (project_fiveper) พัฒนาขึ้นเพื่อเป็นเครื่องมือกลางสำหรับ
นิสิต อาจารย์ประจำวิชา และผู้ดูแลระบบ ในการติดตามความก้าวหน้า ตรวจสอบเป้าหมายโครงการ
และแลกเปลี่ยนข้อเสนอแนะในการทำโครงงาน/โปรเจกต์การศึกษา เพื่อช่วยเพิ่มประสิทธิภาพในการบริหารจัดการ
โครงการ ลดความซ้ำซ้อนของการติดตามงาน และเพิ่มความโปร่งใสในกระบวนการเรียนการสอน

2. ขอบเขตของระบบ (System Scope)
--------------------------------------------------------------------------------
- รองรับการเข้าถึงใช้งานผ่านเว็บแอปพลิเคชัน (Responsive Web Application)
- รองรับสิทธิ์ผู้ใช้งาน 3 บทบาทหลัก: ผู้ดูแลระบบ (Admin), อาจารย์ (Teacher), และ นิสิต (Student)
- รองรับการทำงานแบบ Hybrid Database (Spring Boot REST API + MySQL ในเครื่อง / Supabase Cloud PostgreSQL / LocalStorage Fallback)
- รองรับการใช้งานทั้งบนเครื่อง Local และการติดตั้งบนคลาวด์ (GitHub Pages / Supabase Cloud)

3. ผู้ใช้งานระบบและสิทธิ์การใช้งาน (User Roles & Permissions)
--------------------------------------------------------------------------------
3.1 ผู้ดูแลระบบ (Admin):
    - สามารถจัดการข้อมูลผู้ใช้งานทั้งหมดในระบบ (เพิ่ม, แก้ไข, ลบ, เปลี่ยนบทบาท)
    - สามารถเข้าถึงและจัดการโครงการ เป้าหมาย ข้อเสนอแนะ และภาพรวมทั้งระบบได้
    - เข้าถึงเมนู "จัดการระบบ (User Management)" ได้เพียงบทบาทเดียว

3.2 อาจารย์ (Teacher / Instructor):
    - สามารถเรียกดูโครงการของนิสิตในความดูแล และค้นหาโครงการตามรายวิชาได้
    - สามารถประเมินความก้าวหน้า เพิ่มข้อเสนอแนะ (Feedback) ให้กับนิสิตในแต่ละโครงการได้
    - สามารถเรียกดูแดชบอร์ดสรุปผลการดำเนินงานและรายงานความก้าวหน้ารายวิชาได้

3.3 นิสิต (Student):
    - สามารถสร้าง แก้ไข และติดตามสถานะโครงการของตนเองได้
    - สามารถจัดการเป้าหมาย (Milestone) และอัปเดตเปอร์เซ็นต์ความก้าวหน้าของงานได้
    - สามารถอ่านข้อเสนอแนะจากอาจารย์ที่ส่งถึงโครงการของตนเองได้

4. ข้อกำหนดฟังก์ชันการทำงาน (Functional Requirements - FR)
--------------------------------------------------------------------------------
[FR-1] ระบบยืนยันตัวตนและการเข้าสู่ระบบ (Authentication & Role Authorization)
   - FR-1.1: ผู้ใช้สามารถเข้าสู่ระบบด้วย อีเมล (Email) และ รหัสผ่าน (Password)
   - FR-1.2: ระบบมีปุ่ม "ทดลองเข้าสู่ระบบตามบทบาท (Demo Login)" 3 บทบาท (Admin, Teacher, Student) สำหรับการทดลองใช้งาน
   - FR-1.3: ระบบจะจัดเก็บข้อมูล Session สิทธิ์ผู้ใช้งานปัจจุบันไว้ใน sessionStorage
   - FR-1.4: ระบบตรวจสอบสิทธิ์การเข้าถึงหน้าเว็บ (Role-based Routing) ป้องกันไม่ให้นิสิตหรืออาจารย์เข้าถึงเมนูแอดมิน

[FR-2] ระบบจัดการผู้ใช้งาน (User Management)
   - FR-2.1: ผู้ดูแลระบบสามารถเพิ่มผู้ใช้งานใหม่ โดยกำหนด รหัสผู้ใช้, ชื่อ-นามสกุล, อีเมล, บทบาท และรหัสผ่าน
   - FR-2.2: สามารถแก้ไขข้อมูลผู้ใช้และรีเซ็ตรหัสผ่านได้
   - FR-2.3: สามารถลบผู้ใช้ที่ไม่ต้องการออกจากระบบได้

[FR-3] ระบบจัดการโครงการ (Project Management & Progress Tracking)
   - FR-3.1: นิสิตสามารถเพิ่มโครงการใหม่ โดยระบุ ชื่อโครงการ, รายวิชา, รายละเอียด, วันครบกำหนดส่ง และสถานะ
   - FR-3.2: อาจารย์และแอดมินสามารถดูตารางสรุปโครงการ นิสิตผู้รับผิดชอบ รายวิชา และสถานะการดำเนินงานได้
   - FR-3.3: รองรับสถานะโครงการ 3 รหัส: "ยังไม่เริ่ม", "กำลังดำเนินการ", "เสร็จสิ้น"
   - FR-3.4: รองรับการแก้ไขรายละเอียดและการลบโครงการ

[FR-4] ระบบจัดการเป้าหมาย (Milestone Tracking)
   - FR-4.1: แสดงรายการเป้าหมายหลักไมล์ของโครงการพร้อมกำหนดวันเสร็จสิ้น
   - FR-4.2: สามารถปรับเปลี่ยนเปอร์เซ็นต์ความก้าวหน้า (Progress 0% - 100%) และสถานะการทำงานได้

[FR-5] ระบบข้อเสนอแนะและประเมินผล (Feedback & Review System)
   - FR-5.1: อาจารย์สามารถเลือกโครงการของนิสิต และบันทึกข้อเสนอแนะ/คำแนะนำเชิงลึกได้
   - FR-5.2: บันทึกชื่ออาจารย์ผู้ให้คำแนะนำ วันที่บันทึก และชื่อโครงการกำกับไว้อย่างชัดเจน
   - FR-5.3: นิสิตสามารถเข้าดูประวัติข้อเสนอแนะย้อนหลังที่เกี่ยวข้องกับโครงการของตนเองได้

[FR-6] ระบบแดชบอร์ดและรายงาน (Dashboard & Analytics Reports)
   - FR-6.1: แสดงการ์ดสรุปจำนวนโครงการทั้งหมด, กำลังดำเนินการ, เสร็จสิ้น, และจำนวนรายวิชา
   - FR-6.2: แสดงกราฟแท่ง (Bar Chart) เปรียบเทียบความก้าวหน้าโครงการแยกตามรายวิชา (เช่น CS 101, CS 201, CS 301)
   - FR-6.3: แสดงรายการโครงการล่าสุดในความดูแล

5. ข้อกำหนดด้านเทคนิคและสถาปัตยกรรม (Technical & Non-Functional Requirements)
--------------------------------------------------------------------------------
[NFR-1] สถาปัตยกรรมซอฟต์แวร์และการเชื่อมต่อข้อมูล (Data Architecture)
   - Frontend: Vite + React 18 + TypeScript + Tailwind CSS
   - Backend API: Spring Boot Java (RESTful Controller at http://localhost:8080)
   - Local DB: MySQL (jdbc:mysql://localhost:8700/webdb)
   - Cloud DB: Supabase Cloud PostgreSQL (https://vvxxvetiydnxlokncwun.supabase.co)
   - Data Resilience: มีระบบ Hybrid API Service (api.ts) ตรวจสอบการเชื่อมต่ออัตโนมัติ 
     (Spring Boot Server -> Supabase Cloud DB -> LocalStorage Fallback)

[NFR-2] การออกแบบส่วนติดต่อผู้ใช้ (UI/UX Design)
   - ออกแบบตามหลัก Responsive Web Design รองรับการใช้งานผ่านหน้าจอ Desktop, Tablet, และ Mobile
   - ใช้ชุดสีเขียวการศึกษา (University Green Theme) สะอาด สบายตา อ่านง่าย

[NFR-3] ความปลอดภัยของข้อมูล (Security)
   - ซิงค์ข้อมูลกับ Supabase Cloud ผ่านโปรโตคอล HTTPS พร้อมระบบ SSL Encryption
   - เปิดใช้งาน Row Level Security (RLS) บน Supabase Cloud

6. โครงสร้างฐานข้อมูล (Database Schema)
--------------------------------------------------------------------------------
6.1 ตาราง pf_users (ข้อมูลผู้ใช้งาน):
    - id (BIGINT PRIMARY KEY)
    - user_id (TEXT - รหัสผู้ใช้ เช่น ADM001, STU001)
    - name (TEXT - ชื่อ-นามสกุล)
    - email (TEXT UNIQUE - อีเมล)
    - role (TEXT - บทบาท: ผู้ดูแลระบบ, อาจารย์, นักศึกษา)
    - password (TEXT - รหัสผ่าน)

6.2 ตาราง pf_projects (ข้อมูลโครงการ):
    - id (BIGINT PRIMARY KEY)
    - name (TEXT - ชื่อโครงการ)
    - description (TEXT - รายละเอียด)
    - course (TEXT - รายวิชา)
    - due_date (DATE - วันครบกำหนด)
    - status (TEXT - สถานะ)
    - student (TEXT - ชื่อนิสิตผู้รับผิดชอบ)
    - progress (INT - เปอร์เซ็นต์ความก้าวหน้า)

6.3 ตาราง pf_milestones (ข้อมูลเป้าหมาย):
    - id (BIGINT PRIMARY KEY)
    - name (TEXT - ชื่อเป้าหมาย)
    - due_date (DATE - วันครบกำหนด)
    - status (TEXT - สถานะ)
    - progress (INT - เปอร์เซ็นต์ความก้าวหน้า)

6.4 ตาราง pf_feedback (ข้อมูลข้อเสนอแนะ):
    - id (BIGINT PRIMARY KEY)
    - comment (TEXT - ข้อความเสนอแนะ)
    - instructor_name (TEXT - ชื่ออาจารย์ผู้ให้คำแนะนำ)
    - date (DATE - วันที่บันทึก)
    - project_name (TEXT - ชื่อโครงการที่ได้รับคำแนะนำ)

6.5 ตาราง pf_chart (ข้อมูลสถิติรายวิชา):
    - id (BIGINT PRIMARY KEY)
    - course (TEXT - รหัสวิชา)
    - projects (INT - จำนวนโครงการทั้งหมด)
    - completed (INT - จำนวนโครงการที่เสร็จสิ้น)
