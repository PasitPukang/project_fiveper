1. บทนำ วัตถุประสงค์ และขอบเขตระบบ (Introduction & Scope)
================================================================================
1.1 วัตถุประสงค์ (Purpose):
    ระบบติดตามการดำเนินงานของนิสิต (project_fiveper) มีวัตถุประสงค์เพื่อเป็นแพลตฟอร์มศูนย์กลาง
    ในการบริหารจัดการ ติดตามความก้าวหน้าโครงงานการศึกษา (Senior Projects / Course Projects)
    และประเมินผลการเรียนรู้แบบเรียลไทม์ ช่วยลดช่องว่างการสื่อสารระหว่างนิสิต อาจารย์ประจำวิชา
    และผู้ดูแลระบบ

1.2 ขอบเขตระบบ (Scope):
    - ระบบงานเว็บแอปพลิเคชันรูปแบบ Responsive สองภาษา (ภาษาไทยและภาษาอังกฤษ)
    - รองรับการทำงานร่วมกัน 3 บทบาท: ผู้ดูแลระบบ (Admin), อาจารย์ (Teacher), และ นิสิต (Student)
    - รองรับสถาปัตยกรรมสำรองข้อมูลสามชั้น (Triple-Tier Data Architecture):
      1) Spring Boot Java REST API + Local MySQL Database (Primary Server)
      2) Supabase Cloud PostgreSQL Database (Automated Cloud Sync)
      3) LocalStorage Client Persistence (Offline Resilience Fallback)

2. อภิธานศัพท์และคำศัพท์เฉพาะ (Glossary & Technical Terms)
================================================================================
คำศัพท์          นิยามและความหมาย
--------------------------------------------------------------------------------
SRS             Software Requirements Specification (เอกสารข้อกำหนดความต้องการซอฟต์แวร์)
FR / NFR        Functional Requirement (ความต้องการเชิงฟังก์ชัน) / Non-Functional Requirement (เชิงคุณภาพ)
PDPA            Personal Data Protection Act (พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562)
RTM             Requirement Traceability Matrix (ตารางติดตามความเชื่อมโยงความต้องการและการทดสอบ)
RLS             Row Level Security (ระบบรักษาความปลอดภัยระดับแถวในฐานข้อมูล Supabase Cloud)
Bcrypt          อัลกอริทึมการเข้ารหัสแฮชรหัสผ่านความปลอดภัยสูง (Password Hashing Algorithm)
JWT             JSON Web Token (มาตรฐานโครงสร้างการยืนยันตัวตนและการเข้าถึง API)
RTO             Recovery Time Objective (ระยะเวลาสูงสุดที่ยอมรับได้ในการกู้คืนระบบกลับมาทำงาน)
RPO             Recovery Point Objective (ปริมาณข้อมูลสูงสุดที่ยอมรับให้สูญหายได้)
FK / PK         Foreign Key (คีย์นอกเชื่อมตาราง) / Primary Key (คีย์หลักประจำเป็นแถว)
UAT             User Acceptance Testing (การทดสอบยอมรับระบบโดยผู้ใช้งานจริง)
REST API        Representational State Transfer API (รูปแบบสถาปัตยกรรมบริการเว็บแลกเปลี่ยนข้อมูล JSON)
WCAG            Web Content Accessibility Guidelines (แนวทางการเข้าถึงเนื้อหาเว็บสำหรับทุกคน)

3. สมมติฐานและข้อจำกัดของระบบ (Assumptions & Constraints)
================================================================================
3.1 สมมติฐาน (Assumptions):
    - ผู้ใช้งานมีอุปกรณ์เชื่อมต่ออินเทอร์เน็ตและเว็บเบราว์เซอร์มาตรฐานที่อัปเดตเวอร์ชันแล้ว
    - สถาบันการศึกษามีข้อมูลรายวิชาและรายชื่อนิสิตเพื่อนำเข้าสู่ระบบเริ่มต้น
    - Supabase Cloud ให้บริการ Database Service พร้อม SSL Certificate สมบูรณ์

3.2 ข้อจำกัด (Constraints):
    - จำกัดขนาดไฟล์แนบรายงานประกอบโครงการไม่เกิน 15 MB ต่อไฟล์ (ประเภท PDF, DOCX, ZIP)
    - การประมวลผลออนไลน์บน GitHub Pages ทำงานในรูปแบบ Client-side Rendering (Vite + React)
    - รหัสผ่านผู้ใช้งานทุกบัญชีต้องถูกแฮชด้วย Bcrypt ก่อนจัดเก็บบันทึกลงฐานข้อมูล

4.2 Mermaid Sequence Diagram: กระบวนการเข้าสู่ระบบ (Authentication Flow)

```mermaid
sequenceDiagram
    autonumber
    actor User as ผู้ใช้งาน (Student/Teacher/Admin)
    participant Client as Frontend (Vite React)
    participant API as API Gateway / Service
    participant DB as Database (MySQL / Supabase)

    User->>Client: ป้อน Email และ Password
    Client->>Client: Validate Email & Password format
    Client->>API: POST /api/v1/auth/login
    API->>DB: Query User by Email
    DB-->>API: User Data + Password Hash
    API->>API: Verify Password with Bcrypt
    alt Password Invalid
        API-->>Client: 401 Unauthorized (ERR_AUTH_001)
        Client-->>User: แสดงข้อความรหัสผ่านไม่ถูกต้อง
    else Password Valid
        API->>API: Generate JWT Token & Set Expiration (60 mins)
        API-->>Client: 200 OK (Token + User Role Info)
        Client->>Client: Store Token in sessionStorage
        Client-->>User: Redirect to Role Dashboard
    end
```

5. ข้อกำหนดฟังก์ชันการทำงานอย่างละเอียด (Detailed Functional Requirements: FR-1 - FR-10)
================================================================================

[FR-1] ระบบยืนยันตัวตน สิทธิ์การใช้งาน และเซสชัน (Authentication, Authorization & Session)
   - FR-1.1: การเข้าสู่ระบบ: ตรวจสอบ อีเมล และ รหัสผ่าน คืนค่า JWT Token พร้อม Role
   - FR-1.2: การสมัครสมาชิก (Registration): นิสิตและอาจารย์สามารถลงทะเบียนเพิ่มบัญชีใหม่ได้
   - FR-1.3: ลืมรหัสผ่าน (Forgot Password): ระบบส่งลิงก์รีเซ็ตรหัสผ่านไปยังอีเมลผู้ใช้ (ย้อนหลัง 15 นาที)
   - FR-1.4: การออกจากระบบ (Logout): ล้างข้อมูล JWT Token และ sessionStorage ทันที
   - FR-1.5: การหมดเวลาเซสชัน (Session Timeout): หากไม่มีการโต้ตอบเกิน 60 นาที ระบบจะตัดเซสชันและบังคับเข้าสู่ระบบใหม่
   - Acceptance Criteria: เมื่อไม่เคลื่อนไหวครบ 60 นาที หน้าจอต้องแสดงแจ้งเตือน "Session Expired" และส่งกลับหน้า Login

[FR-2] กฎการตรวจสอบความถูกต้องข้อมูล (Data Validation Rules)
   - FR-2.1: รูปแบบอีเมล: ต้องเป็นอีเมลสถาบันถูกต้อง (เช่น user@ku.th หรือ user@university.ac.th)
   - FR-2.2: นโยบายรหัสผ่าน: ความยาวไม่น้อยกว่า 8 ตัวอักษร ประกอบด้วยอักขระตัวพิมพ์ใหญ่ ตัวพิมพ์เล็ก และตัวเลข
   - FR-2.3: ความซ้ำซ้อนของรหัสประจำตัว: user_id และ email ต้องไม่ซ้ำกันในระบบ (Unique Constraint)
   - Acceptance Criteria: หากกรอกรหัสผ่านไม่ตรงตามนโยบาย ระบบต้องแสดงข้อความเตือนสีแดงทันทีใต้ช่องกรอกข้อมูล

[FR-3] ระบบจัดการโครงการและกลุ่มงาน (Project & Group Management)
   - FR-3.1: การจัดการโครงการกลุ่ม: รองรับโครงการเดี่ยวและโครงการกลุ่ม (มีสมาชิกได้สูงสุด 5 คนต่อโครงการ บันทึกลงตาราง pf_project_members)
   - FR-3.2: การแนบไฟล์ประกอบ: รองรับการอัปโหลดไฟล์รายงานหรือข้อเสนอโครงการ (ไฟล์ PDF, DOCX, ZIP ไม่เกิน 15 MB)
   - FR-3.3: การระบุอาจารย์ที่ปรึกษา: โครงการต้องเชื่อมโยงกับ teacher_id ของอาจารย์ผู้ดูแล
   - Acceptance Criteria: นิสิตสามารถเพิ่มเพื่อนร่วมกลุ่มได้สูงสุด 4 คน (รวมตนเองเป็น 5 คน) และระบบต้องบันทึกสิทธิ์หัวหน้าโครงการ/สมาชิกกลุ่มลงฐานข้อมูล

[FR-4] ระบบเป้าหมายและแจ้งเตือนวันครบกำหนด (Milestones & Due Date Reminders)
   - FR-4.1: นิสิตสร้างเป้าหมาย (Milestone) และเสนอให้อาจารย์อนุมัติ (is_approved Status)
   - FR-4.2: การแจ้งเตือนวันครบกำหนด: แจ้งเตือนล่วงหน้า 3 วันก่อนถึงกำหนดส่งงาน ผ่านทั้ง In-App Notification Banner และ Email Notification
   - Acceptance Criteria: ระบบส่งการแจ้งเตือน In-App Banner และส่งอีเมลอัตโนมัติหานิสิตล่วงหน้า 3 วันก่อนถึง due_date

[FR-5] ระบบข้อเสนอแนะและการโต้ตอบ (Interactive Feedback System)
   - FR-5.1: อาจารย์บันทึกข้อเสนอแนะกำกับรายโครงการ
   - FR-5.2: นิสิตสามารถกดปุ่ม "ตอบกลับ (Reply)" เพื่อสอบถามเพิ่มเติมในข้อเสนอแนะนั้นได้
   - FR-5.3: ระบบมีสถานะการอ่านข้อเสนอแนะ ("ยังไม่อ่าน" / "อ่านแล้ว") พร้อมแสดง Badge จำนวนข้อเสนอแนะที่ยังไม่ได้อ่าน
   - Acceptance Criteria: เมื่อนิสิตเปิดอ่านข้อเสนอแนะ ระบบจะอัปเดต field is_read เป็น TRUE และลดจำนวน Badge บนเมนู

[FR-6] ระบบแดชบอร์ดและการวิเคราะห์ข้อมูล (Dashboard & Analytics Reports)
   - FR-6.1: สรุปข้อมูลภาพรวม (Summary Cards): จำนวนโครงการทั้งหมด, กำลังดำเนินการ, เสร็จสิ้น, และจำนวนรายวิชา
   - FR-6.2: กราฟแท่งเปรียบเทียบ (Bar Chart): แสดงความก้าวหน้าโครงการแยกตามรายวิชา (CS 101 - CS 401)
   - FR-6.3: รายการโครงการล่าสุด: แสดง 5 โครงการล่าสุดที่อัปเดตความก้าวหน้า
   - FR-6.4: การกรองแดชบอร์ดตามบทบาท: แดชบอร์ดนิสิตแสดงเฉพาะงานตนเอง, แดชบอร์ดอาจารย์แสดงงานในดูแล, แดชบอร์ดแอดมินแสดงภาพรวมทั้งมหาวิทยาลัย
   - Acceptance Criteria: ข้อมูลการ์ดสรุปและกราฟบนแดชบอร์ดต้องอัปเดตเรียลไทม์ตรงตามข้อมูลล่าสุดในฐานข้อมูล

[FR-7] ระบบการแจ้งเตือนแบบเรียลไทม์ (Notification System)
   - FR-7.1: แจ้งเตือนศูนย์กลาง (Notification Center): แสดงรายการแจ้งเตือนทั้งหมดในตาราง pf_notifications
   - FR-7.2: แจ้งเตือนเมื่อมี Feedback ใหม่จากอาจารย์ หรือเมื่อมีการอัปเดตสถานะโครงการ
   - Acceptance Criteria: ไอคอนกระดิ่งแจ้งเตือนแสดงตัวเลขแดงเมื่อมีข้อความใหม่ และคลิกเพื่อดูรายละเอียดได้

[FR-8] ระบบค้นหา และกรองข้อมูลขั้นสูง (Advanced Search & Filter System)
   - FR-8.1: ค้นหาโครงการตาม ชื่อโครงการ, ชื่อคอมพิวเตอร์นิสิต, รหัสวิชา (CS 101 - CS 401)
   - FR-8.2: กรองสถานะโครงการ: "ยังไม่เริ่ม", "กำลังดำเนินการ", "เสร็จสิ้น"
   - Acceptance Criteria: ผลการค้นหาและกรองข้อมูลแสดงผลลัพธ์ภายในเวลาไม่เกิน 100 มิลลิวินาที

[FR-9] ระบบส่งออกรายงาน (Report Export System)
   - FR-9.1: อาจารย์และแอดมินสามารถส่งออกรายงานสรุปความก้าวหน้าเป็นไฟล์ PDF และ Excel (XLSX)
   - Acceptance Criteria: ไฟล์ที่ส่งออกต้องมีหัวรายงาน ชื่อวิชา สถิติเปอร์เซ็นต์ความก้าวหน้า และรายชื่อนิสิตครบถ้วน

[FR-10] ระบบบันทึกประวัติการเปลี่ยนแปลง (Audit Logging System)
   - FR-10.1: บันทึกการกระทำสำคัญ (Create, Update, Delete) โดยเก็บ User ID, Action, Details, IP Address, Timestamp ลงตาราง pf_audit_logs
   - Acceptance Criteria: ทุกการลบผู้ใช้ หรือการแก้ไขสิทธิ์ระบบ ต้องถูกบันทึกลง pf_audit_logs โดยไม่สามารถลบแก้ไขบันทึกประวัติได้

6. ข้อกำหนดด้านคุณภาพและประสิทธิภาพ (Non-Functional Requirements: NFR)
================================================================================

[NFR-1] ประสิทธิภาพการทำงาน (Performance)
   - เวลาโหลดหน้าเว็บ (Page Load Time): ไม่เกิน 2.0 วินาทีในเครือข่ายปกติ
   - เวลาตอบสนอง API (API Response Time): ไม่เกิน 200 มิลลิวินาที (P95)
   - การรองรับผู้ใช้งานพร้อมกัน (Concurrent Users): ไม่น้อยกว่า 500 ผู้ใช้งานพร้อมกันโดยระบบไม่ล่ม

[NFR-2] ความพร้อมใช้งานและการกู้คืน (Availability & Reliability)
   - Uptime เป้าหมาย: 99.9% ต่อปี (Downtime ไม่เกิน 8.76 ชั่วโมง/ปี)
   - ระบบสำรองฉุกเฉิน (Automatic Failover Fallback): หาก Spring Boot Local Server ไม่ตอบสนองภายใน 1.5 วินาที
     ระบบจะสลับไปดึงข้อมูลจาก Supabase Cloud DB หรือ LocalStorage โดยอัตโนมัติโดยผู้ใช้ไม่หลุดจากหน้าเว็บ

[NFR-3] การขยายตัวของระบบ (Scalability)
   - รองรับจำนวนนิสิตสูงสุด 10,000 คน และโครงการรวมมากกว่า 50,000 โครงการ

[NFR-4] การสำรองและกู้คืนข้อมูล (Backup & Recovery)
   - ความถี่ในการสำรองข้อมูล Cloud DB: สำรองข้อมูลอัตโนมัติทุก 24 ชั่วโมง
   - Recovery Time Objective (RTO): ไม่เกิน 30 นาที
   - Recovery Point Objective (RPO): ไม่เกิน 1 ชั่วโมง

[NFR-5] ความเข้ากันได้กับเบราว์เซอร์ (Browser & Device Compatibility)
   - Google Chrome (v100+), Microsoft Edge (v100+), Apple Safari (v15+), Mozilla Firefox (v100+)
   - รองรับการแสดงผลสมบูรณ์แบบบนระบบปฏิบัติการ Windows, macOS, iOS และ Android

[NFR-6] ความปลอดภัยของรหัสผ่านและข้อมูล (Security & Password Encryption)
   - รหัสผ่านผู้ใช้งานต้องผ่านการเข้ารหัสแฮชด้วย Bcrypt (Cost Factor 12) ก่อนบันทึกลง DB (ห้ามเก็บ Plain Text)
   - การรับส่งข้อมูลทั้งหมดบน Cloud ผ่านโปรโตคอล HTTPS SSL/TLS 1.3
   - ตาราง Supabase Cloud มีการเปิดใช้งาน Row Level Security (RLS) กำหนดสิทธิ์การเข้าถึงข้อมูลตาม JWT Role

[NFR-7] การจัดการข้อผิดพลาดและบันทึกร่องรอย (Error Handling & Logging)
   - รูปแบบ Error Response มาตรฐาน: { "status": 400/500, "code": "ERR_XXX", "message": "...", "timestamp": "..." }
   - บันทึก System Log แยกระดับ INFO, WARN, ERROR ลงในไฟล์ log ประจำวัน

[NFR-8] การออกแบบการใช้งานและการเข้าถึงสำหรับทุกคน (UI/UX Design & Accessibility)
   - ออกแบบส่วนติดต่อผู้ใช้งานตามหลัก Responsive Design (Mobile-First Touch Targets >= 44x44px)
   - ใช้ธีมสีเขียวมหาวิทยาลัย (University Green Theme: #16a34a / #22c55e) ที่มีค่าความต่างสี (Color Contrast Ratio) >= 4.5:1 ตามมาตรฐาน WCAG 2.1 Level AA

7.1 Diagram สรุปความสัมพันธ์ (Entity-Relationship Specs):
    - pf_users (1) <--- (N) pf_projects (teacher_id)
    - pf_users (1) <--- (N) pf_project_members (student_id)
    - pf_projects (1) <--- (N) pf_project_members (project_id)
    - pf_projects (1) <--- (N) pf_milestones (project_id)
    - pf_projects (1) <--- (N) pf_feedback (project_id)
    - pf_users (1) <--- (N) pf_notifications (user_id)
    - pf_users (1) <--- (N) pf_audit_logs (user_id)

7.2 โครงสร้างตารางฐานข้อมูลฉบับสมบูรณ์ (SQL Definition Specs):

-- 1. ตารางข้อมูลผู้ใช้งาน (pf_users)
CREATE TABLE pf_users (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id VARCHAR(50) NOT NULL UNIQUE,
  name VARCHAR(150) NOT NULL,
  email VARCHAR(150) NOT NULL UNIQUE,
  role VARCHAR(30) CHECK (role IN ('ผู้ดูแลระบบ', 'อาจารย์', 'นักศึกษา')),
  password_hash VARCHAR(255) NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 2. ตารางข้อมูลโครงการ (pf_projects)
CREATE TABLE pf_projects (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name VARCHAR(200) NOT NULL,
  description TEXT,
  course VARCHAR(50) NOT NULL,
  due_date DATE,
  status VARCHAR(30) DEFAULT 'กำลังดำเนินการ',
  student_id BIGINT REFERENCES pf_users(id) ON DELETE SET NULL,
  teacher_id BIGINT REFERENCES pf_users(id) ON DELETE SET NULL,
  student VARCHAR(150),
  attachment_url TEXT,
  progress INT DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 3. ตารางสมาชิกกลุ่มโครงการ (pf_project_members) - รองรับ Group Projects (FR-3.1)
CREATE TABLE pf_project_members (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  project_id BIGINT REFERENCES pf_projects(id) ON DELETE CASCADE,
  student_id BIGINT REFERENCES pf_users(id) ON DELETE CASCADE,
  role_in_team VARCHAR(30) DEFAULT 'สมาชิก' CHECK (role_in_team IN ('หัวหน้าโครงการ', 'สมาชิก')),
  joined_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(project_id, student_id)
);

-- 4. ตารางเป้าหมายและหลักไมล์ (pf_milestones)
CREATE TABLE pf_milestones (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  project_id BIGINT REFERENCES pf_projects(id) ON DELETE CASCADE,
  name VARCHAR(200) NOT NULL,
  due_date DATE,
  status VARCHAR(30) DEFAULT 'ยังไม่เริ่ม',
  progress INT DEFAULT 0,
  is_approved BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 5. ตารางข้อเสนอแนะ (pf_feedback)
CREATE TABLE pf_feedback (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  project_id BIGINT REFERENCES pf_projects(id) ON DELETE CASCADE,
  instructor_id BIGINT REFERENCES pf_users(id) ON DELETE SET NULL,
  comment TEXT NOT NULL,
  instructor_name VARCHAR(150),
  date DATE DEFAULT CURRENT_DATE,
  project_name VARCHAR(200),
  is_read BOOLEAN DEFAULT FALSE,
  reply_comment TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 6. ตารางการแจ้งเตือน (pf_notifications)
CREATE TABLE pf_notifications (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id BIGINT REFERENCES pf_users(id) ON DELETE CASCADE,
  title VARCHAR(200) NOT NULL,
  message TEXT NOT NULL,
  is_read BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 7. ตารางบันทึกประวัติ (pf_audit_logs)
CREATE TABLE pf_audit_logs (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id BIGINT REFERENCES pf_users(id) ON DELETE SET NULL,
  action VARCHAR(100) NOT NULL,
  details TEXT,
  ip_address VARCHAR(50),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 8. ตารางสถิติตามรายวิชา (pf_chart)
CREATE TABLE pf_chart (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  course VARCHAR(50) NOT NULL UNIQUE,
  projects INT DEFAULT 0,
  completed INT DEFAULT 0,
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

     - เมื่อครบกำหนด 5 ปี ข้อมูลส่วนบุคคลจะถูกเข้ารหัสแบบไม่สามารถระบุตัวตนได้ (Anonymization) หรือลบทิ้งอย่างปลอดภัย
